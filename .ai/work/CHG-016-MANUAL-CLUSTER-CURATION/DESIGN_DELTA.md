## Problem and user outcome

Analysts need to add a missing support topic and refine its source pairs without
leaving the Explorer. The flow must support both a fully manual empty cluster and a
sample-driven cluster whose initial FAQ metadata is generated by an LLM.

## Current experience

The Explorer table exposes existing cluster summaries and a separate row-level edit
form with a Save button. The source dialog is read-only. Cluster creation is owned by
the Cluster-Set workflow and does not support a manual empty cluster.

## Desired experience

The Explorer action rail opens a compact manual-cluster flow. The analyst chooses
empty/manual or example-driven mode, enters examples and basis/scope when relevant,
reviews matches, and confirms creation. Existing table values become inline editable
cells with autosave feedback. Each source row gains a clearly labeled “In Outliers
verschieben” action.

## User flow

1. Open “Manuelles Cluster anlegen”.
2. Choose “Leeres Cluster” or “Mit Beispielen”.
3. For empty mode, enter title, category, FAQ question and FAQ answer.
4. For example mode, enter one or more bounded examples, choose message/answer,
   source scope, provider/model and cloud confirmation where applicable.
5. Start preview; show loading, validation, provider failure and no-result states.
6. Review similarity results and select pairs. Show current cluster/outlier state.
7. Confirm; create/switch to the manual-edit child and show success state.
8. On any cluster, choose “Mit LLM aktualisieren”; show provider/sample progress and
   update only that cluster's four summary fields after success.
9. In the source dialog, select one or more sources as references, choose message or
   answer and a scope, then show similarity results without changing memberships.
10. In the table, click a title/category/FAQ cell to edit; save on blur/commit and
   show a small local pending/saved/error state. Status saves on change.
11. In the source dialog, move one source to Outliers; update the list only after
   success and announce the result.

## State inventory

- default: mode-specific empty form with accessible labels and explanation.
- loading: bounded provider/search progress at the affected form/preview/cluster row.
- empty: empty manual mode; no-result preview with threshold/basis recovery.
- error: safe form/banner, cluster-row or source-dialog alert; no raw provider/source internals.
- validation: field-level required/bounds messages; values preserved.
- disabled: submit/actions disabled while mutation is pending; controls remain labeled.
- submitting: explicit pending state; no duplicate mutation; refresh never changes memberships.
- success: status/feedback after server commit; Explorer/cluster source refresh.
- long content: bounded textareas/cells and internal dialog/preview scrolling.
- small viewport: stacked form/preview, horizontal table scroll, reachable actions.
- permission restricted: safe API error and unchanged state.
- partial data: source page/reference-match/single-summary failure leaves existing Explorer state usable.

## Responsive behavior

Use the existing 980px breakpoint. Desktop uses a two-region form/preview layout
where space permits; mobile stacks fields, preview results and actions. Source actions
remain reachable within the dialog row and table retains horizontal scrolling.

## Component impact

### Existing components reused

Explorer rail, source dialog, table, semantic controls, feedback overlay, status chips,
focus trap, selection controls and existing error/status regions.

### Existing components extended

Feature-local cluster row editor, single-summary action state, reference selection and
search-preview state, and source row action group.

### New shared components

none proposed.

### New feature-local components

One manual-cluster creation/preview composition, kept local unless reuse search proves
that a shared component is warranted.

### Components replaced or removed

The row-level Save form is removed after autosave equivalence is verified.

### Rejected reuse options

Separate page/editor and a new component library would duplicate the Explorer owner
and add no required capability.

### Rationale

Reuse keeps table/dialog behavior and accessibility consistent; only the new
multi-step creation flow needs a new composition.

## Accessibility requirements

Inline editing must expose an accessible name and commit/cancel keyboard behavior;
status and save failures use live regions. The preview selection is keyboard
operable with a visible selection state. Dialog focus is trapped and returned to the
source action. Long support text remains readable without clipping.

## Error experience

### Action and failure inventory

| Action | Failure | Error code | User message | Placement | Recovery action |
|---|---|---|---|---|---|
| Create empty | missing fields | `CLUSTER_MANUAL_CREATE_INVALID` | Pflichtfelder prüfen. | inline/form | correct input |
| Create from examples | provider/schema/cloud failure | `CLUSTER_MANUAL_SUMMARY_FAILED` | Felder konnten nicht erstellt werden. | form banner | provider/manual mode/retry |
| Preview | provider/budget/no result | `CLUSTER_MANUAL_MATCH_FAILED` / `CLUSTER_MANUAL_MATCH_EMPTY` | Suche fehlgeschlagen/keine Treffer. | preview | adjust/retry |
| Single-cluster LLM refresh | provider/schema/timeout | `CLUSTER_SINGLE_SUMMARY_FAILED` | Clusterzusammenfassung konnte nicht aktualisiert werden. | cluster row | retry/provider |
| Reference search | invalid scope/selection/provider/no result | `CLUSTER_REFERENCE_SELECTION_INVALID` / `CLUSTER_REFERENCE_SEARCH_FAILED` / `CLUSTER_REFERENCE_SEARCH_EMPTY` | Referenzsuche konnte nicht ausgeführt werden oder ergab keine Treffer. | source dialog/preview | correct/retry |
| Inline save | validation/conflict/network | `CLUSTER_MANUAL_EDIT_CONFLICT` | Änderung nicht gespeichert. | cell/status | rollback/reload |
| Move source | conflict/not found/transaction | `CLUSTER_MANUAL_SOURCE_MOVE_FAILED` | Quelle nicht verschoben. | dialog alert | retry/reload |

### Error presentation levels

- Inline field error: required and bounded create fields.
- Form-level banner: LLM, provider, preview and creation failures.
- Component-level error: preview, single-summary row and source dialog failures.
- Page-level error: existing Explorer load fallback.
- Toast or transient notification: supplementary success only after commit.
- Fatal application fallback: existing React boundary/unknown fallback.

### Input preservation

Keep entered examples, form values, filters, selected matches and source rows after
recoverable failure. Roll back optimistic inline values to the last server value.

### Focus behavior

Focus the first invalid field; keep focus in the active inline cell after failed save;
return focus to the source action after dialog close; focus the affected alert only
when needed for recovery.

### Recovery behavior

Retry provider/search/move, correct input, adjust scope/basis, reload on conflict,
and preserve manual mode selection.

### Unknown error fallback

Use the central safe fallback with a safe correlation reference, no raw text or
technical detail, and retain safe draft/filter state.

### Error-state evidence

Required in approved prototype and revision-bound browser evidence for desktop/mobile.
